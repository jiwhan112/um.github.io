Palindrome Permutation — 유적 암호의 대칭 배치

글자들의 순서를 실제로 전부 바꿔보지 않고도 회문을 만들 수 있는지 판단하는 방법을 탐구합니다.

문제힌트직접 코딩해설검증

1. 문제 이해하기

문자 타일을 좌우 대칭으로 재배열할 수 있을까?

유적에는 영문자와 공백으로 이루어진 암호가 적혀 있습니다. 공백을 무시하고 대소문자를 구별하지 않을 때, 남은 문자를 어떤 순서로든 재배열해서 좌우가 같은 회문을 만들 수 있다면 true를 반환하는 함수를 구현합니다. 실제 회문을 생성할 필요는 없습니다.

입력 및 제한 조건

입력은 std::string 하나이고 허용되는 문자는 ASCII 영문자 A~Z, a~z 및 공백뿐입니다. 다른 문자(숫자, 구두점, UTF-8 다국어 등)는 false를 반환합니다. 빈 문자열 또는 공백만 있어도 빈 회문을 구성할 수 있다고 정의합니다.

예시: "Race Car" → true, "CATS" → false

2. 코딩 전에 답할 질문

  1. 대칭이므로 가운데 이외에 어떤 조건으로 문자들이 짝지어져야 하나요?
  2. 홀수 횟수 등장한 문자는 몇 종류까지 허용될까요?
  3. 26개의 등장 횟수를 모두 저장해야 할까요, 아니면 홀짝만 기억하면 충분할까요?

3. 힌트 및 그림

자신의 풀이를 먼저 생각한 다음 필요한 힌트만 펼쳐 보세요.

힌트 1: 글자의 짝

회문의 양끝 글자는 서로 같습니다. 대부분 글자는 두 개씩 필요합니다.

힌트 2: 가운데 하나

홀수 길이의 회문이라면 가운데 글자 하나만 홀수 번 등장할 수 있습니다.

힌트 3: 비트 연산

등장할 때마다 해당 글자 위치의 한 비트를 XOR로 뒤집으면 홀짝 상태만 기억할 수 있습니다.

🧩 그림으로 보는 핵심 원리 (풀이 스포일러 포함)

회문 R A C E C A R에서는 가운데 E만 한 번, 나머지 문자는 각각 두 번 등장합니다.

5. 검증된 풀이

✅ C++11 코드 · 알고리즘 증명 · 복잡도 펼치기

풀이 원리

회문에서는 모든 문자들이 양 끝에서 짝으로 등장하고, 홀수 길이의 경우 가운데 놓이는 문자 한 종류만 홀수 횟수여도 됩니다. 따라서 홀수 횟수인 문자의 종류가 0개 또는 1개인지 확인하면 충분합니다.

각 문자에 26개 비트 중 한 비트를 대응시키고 등장할 때마다 XOR로 토글합니다. 전부 0이거나, oddBits & (oddBits - 1)이 0이면 켜진 비트가 하나 이하이므로 회문 구성 가능합니다.

#include <cstdint>
#include <string>

bool CanArrangePalindrome(const std::string& input) {
    std::uint32_t oddBits = 0;
    for (unsigned char ch : input) {
        if (ch == ' ') continue;
        if (ch >= 'A' && ch <= 'Z')
            ch = static_cast<unsigned char>(ch - 'A' + 'a');
        if (ch < 'a' || ch > 'z') return false;
        const unsigned index = ch - 'a';
        oddBits ^= (std::uint32_t{1} << index);
    }
    return oddBits == 0 || (oddBits & (oddBits - 1)) == 0;
}

복잡도

시간 O(n)으로 전체 글자를 한 번 읽고, 입력과 무관한 32비트 마스크만 사용하므로 추가 공간 O(1)입니다.

놓치기 쉬운 조건

  • 실제 회문을 만들어야 하는 것은 아님
  • 대소문자를 구별하지 않도록 ASCII 대문자를 소문자로 변환
  • 공백 이외의 문자는 임의로 무시하지 않음
  • 빈 문자열은 조건상 true로 취급
  • 비트 이동 이전에 문자 인덱스가 0~25인지 검사

위 코드는 C++11 컴파일 및 자체 경계 사례 테스트를 통과했습니다.
