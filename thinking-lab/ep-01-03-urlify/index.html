URLify — 미니맵 위치 문자열의 공백 인코딩

원본 문자열을 뒤에서부터 읽고 쓰면 어떻게 안전하게 긴 문자열로 확장할 수 있을까요?

도서의 장·문항 순서를 참고한 자체 제작 문제입니다. 학습 배정일은 10월 9일부터 하루 한 회차로 소급 배치한 날짜이며 실제 게시일과는 구분합니다.

문제힌트직접 코딩해설검증

1. 문제 이해하기

공백을 포함한 위치 이름을 주소에 사용할 문자열로 변환하기

미니맵의 위치 이름에 포함된 공백(ASCII 0x20)을 각각 %20으로 바꾸는 함수를 작성합니다. 원래 이름은 버퍼 앞쪽에 있고, used가 원래 길이입니다. 뒤에는 이미 충분한 여유 공간이 확보되어 있습니다. 추가 문자열 배열 없이 버퍼 안에서 변환해야 합니다.

입력 및 제한 조건

std::string& buffer와 std::size_t used. 원본 buffer[0..used)는 ASCII 문자만 허용합니다. 필요한 결과 용량이 이미 buffer.size() 안에 있어야 하며, 공간 부족·잘못된 길이·비 ASCII 입력은 false를 반환하고 원본을 보존합니다. 성공 시 true를 반환하고 결과 길이로 resize합니다.

예시: "MAP ROOM ", used=8 → "MAP%20ROOM"

2. 코딩 전에 답할 질문

  1. 공백 하나를 3글자로 바꿀 때 결과 길이는 얼마나 늘어날까요?
  2. 문자열의 앞에서부터 바꾸면 어떤 데이터가 덮일 수 있나요?
  3. 읽기 포인터와 쓰기 포인터를 어디에 두어야 할까요?

3. 힌트 및 그림

자신의 풀이를 먼저 생각한 다음 필요한 힌트만 펼쳐 보세요.

힌트 1: 공간 산정

공백 수 k를 센 뒤 required = used + 2*k 를 먼저 계산하세요.

힌트 2: 커서 방향

원래 데이터의 뒤에서부터 읽으면 아직 읽지 않은 문자를 덮지 않을 수 있습니다.

힌트 3: 쓰는 순서

뒤에서 쓰므로 공백을 보면 0, 2, % 순서로 써야 최종적으로 %20이 됩니다.

🧩 그림으로 보는 핵심 원리 (풀이 스포일러 포함)

공백 한 개를 %20으로 치환한 모습입니다. 강조된 세 칸은 새로 채워진 문자열입니다.

5. 검증된 풀이

✅ C++11 코드 · 알고리즘 증명 · 복잡도 펼치기

풀이 원리

먼저 원래 구간의 공백 개수와 ASCII 제약을 확인합니다. required = used + 2*spaces로 필요한 결과 길이를 계산합니다. 읽기 위치는 used, 쓰기 위치는 required에서 시작해 둘 다 뒤에서부터 앞으로 이동합니다. 쓰기 영역이 읽지 않은 원본 문자보다 뒤에 있으므로 원본을 덮지 않습니다.

오류는 쓰기 시작 전에 모두 검사하므로 실패할 때 원본이 그대로 유지됩니다.

#include <cstddef>
#include <limits>
#include <string>

bool EncodeSpacesInPlace(std::string& buffer, std::size_t used) {
    if (used > buffer.size()) return false;
    std::size_t spaces = 0;
    for (std::size_t i = 0; i < used; ++i) {
        const unsigned char ch = static_cast<unsigned char>(buffer[i]);
        if (ch > 127) return false;
        if (ch == ' ') ++spaces;
    }
    if (spaces > (std::numeric_limits<std::size_t>::max() - used) / 2)
        return false;
    const std::size_t required = used + 2 * spaces;
    if (required > buffer.size()) return false;
    std::size_t read = used, write = required;
    while (read > 0) {
        const char ch = buffer[--read];
        if (ch == ' ') {
            buffer[--write] = '0';
            buffer[--write] = '2';
            buffer[--write] = '%';
        } else {
            buffer[--write] = ch;
        }
    }
    buffer.resize(required);
    return true;
}

복잡도

시간 O(n), 추가 작업 공간 O(1)입니다. 결과를 위한 공간이 기존 입력 버퍼에 이미 확보돼 있다는 조건을 사용합니다.

놓치기 쉬운 조건

  • used와 buffer.size()는 서로 다름
  • 공백을 앞에서부터 확장하면 원본 데이터가 덮일 수 있음
  • ASCII 외의 UTF-8 문자는 이 문제에서 허용하지 않음
  • 공간 부족은 쓰기 전에 검출하여 입력을 변경하지 않음

위 코드는 C++11 컴파일 및 자체 경계 사례 테스트를 통과했습니다.
