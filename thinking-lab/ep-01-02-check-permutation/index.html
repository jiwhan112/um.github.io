🧩 핵심 개념부터 이해하기

문자열 일치

같은 위치에 같은 문자가 있어야 합니다. AB와 BA는 다른 문자열입니다.

순열 관계

문자의 배치는 달라도 됩니다. 그러나 각 문자가 등장하는 횟수는 같아야 합니다.

한 문장 질문: AAB와 ABB는 문자 종류가 똑같이 A, B인데도 같은 구성일까요? 결과뿐 아니라 이유를 먼저 적어 보세요.

🎯 자체 제작 문제 · 로비 배지 토큰 재배열 검사

요구 사항

게임 로비의 배지 코드는 대문자 또는 숫자로 이루어진 문자열입니다. 두 코드에 포함된 각 문자의 종류와 개수가 완전히 같다면 순서가 달라도 같은 토큰 구성으로 판정합니다.

두 문자열 left, right를 받아 같은 구성이면 true, 다르면 false를 반환하는 함수를 작성하세요. 입력 문자열 자체를 수정해서는 안 됩니다.

bool HaveSameCodeTokens(const std::string& left, const std::string& right);

제약 조건 · 인코딩 · 반환값

  • 길이: 각각 0~200,000 문자. 길이가 달라도 입력할 수 있습니다.
  • 허용 문자: ASCII A~Z와 0~9만 허용합니다(총 36종). 대소문자를 자동 변환하지 않습니다.
  • 인코딩: 이 문제는 ASCII 전용이므로 1문자 = 1바이트입니다. std::string::size()로 문자의 개수를 비교할 수 있습니다. UTF-8 다중 바이트 문자는 취급하지 않습니다.
  • 중복: 한 문자가 여러 번 나오는 경우 그 횟수까지 정확히 같아야 합니다.
  • 빈 문자열: 두 입력이 모두 빈 문자열이면 true입니다. 함수는 허용 문자가 아닌 값을 전달받으면 안전하게 false를 반환하도록 만드세요.
예제 1
left  = "AAB2C"
right = "C2ABA"
결과  = true
예제 2
left  = "AA12"
right = "A112"
결과  = false

입출력은 C++ 함수 인자와 반환값 기준입니다. 콘솔의 공백 구분 입력 형식은 따로 정의하지 않아 빈 문자열도 정상적으로 검사할 수 있습니다.

🧠 스스로 풀기 위한 질문과 단계별 힌트

  1. 두 문자열의 길이가 다르면 순서를 바꾸는 것만으로 같아질 수 있을까요?
  2. 두 문자열에 등장한 문자의 종류만 같으면 충분할까요? AAA1과 A111을 생각해 보세요.
  3. 정렬한 두 문자열을 비교한다면 얼마나 걸릴까요? 문자가 36종이라는 조건을 이용하면 정렬을 피할 수 있을까요?
힌트 1 · 바뀌지 않는 성질

문자의 순서를 섞어도 문자열의 길이나 각 문자의 등장 횟수는 변하지 않습니다. 먼저 쉽게 확인할 조건부터 찾아보세요.

힌트 2 · 쉬운 방식부터

두 문자열을 복사해서 각각 정렬하면 비교하기 쉬워집니다. 더 빠르게 하려면 무엇을 저장해야 할지 생각해 보세요.

힌트 3 · 고정된 36종

숫자 10개와 알파벳 26개를 0~35번 칸에 대응시킬 수 있습니다. 한쪽에서 등장한 만큼 더하고, 다른 쪽에서 등장한 만큼 빼면 어떨까요?

✅ 모범 풀이와 정확성 증명

직접 작성한 풀이와 비교할 준비가 되었을 때 아래를 펼치세요.

정답 코드 · 설명 · 복잡도 펼치기

아이디어: 문자별로 왼쪽 등장 횟수 - 오른쪽 등장 횟수를 누적합니다. 처음에는 모두 0이며, 끝까지 처리한 후 한 칸도 남지 않으면 같은 구성입니다.

#include <array>
#include <cstddef>
#include <string>

// '0'~'9'는 0~9, 'A'~'Z'는 10~35에 대응.
// 그 외의 값은 유효하지 않음을 뜻하는 -1.
int TokenIndex(char c) {
    if (c >= '0' && c <= '9') {
        return c - '0';
    }
    if (c >= 'A' && c <= 'Z') {
        return 10 + (c - 'A');
    }
    return -1;
}

bool HaveSameCodeTokens(const std::string& left,
                        const std::string& right) {
    if (left.size() != right.size()) {
        return false;
    }

    std::array<int, 36> delta = {};

    for (std::size_t i = 0; i < left.size(); ++i) {
        const int a = TokenIndex(left[i]);
        const int b = TokenIndex(right[i]);
        if (a < 0 || b < 0) {
            return false;
        }
        ++delta[static_cast<std::size_t>(a)];
        --delta[static_cast<std::size_t>(b)];
    }

    for (int value : delta) {
        if (value != 0) {
            return false;
        }
    }
    return true;
}

왜 정확한가? · 반복문 불변식

  1. 처음에는 모든 칸의 값이 0입니다.
  2. 인덱스 i를 처리한 뒤 각 칸에는 left의 처음 i+1개에 나타난 문자 수 − right의 처음 i+1개에 나타난 문자 수가 저장됩니다.
  3. 전체 순회 후 모든 칸이 0이면 36종 각각의 전체 등장 횟수가 같습니다. 반대로 하나라도 0이 아니라면 순서를 바꿔도 그 문자 수가 바뀌지 않으므로 같은 구성일 수 없습니다.
핵심 반례 · 중간에 차이가 있다고 바로 중단하면 안 됩니다.

left="AB", right="BA"는 첫 번째 문자에서 수량 차이가 생겨도 끝나면 모두 0이 됩니다. 길이 검사와 유효하지 않은 문자의 검사만 먼저 종료해도 안전합니다.

시간 및 추가 공간 복잡도

시간 O(n + 36) = O(n)

같은 길이의 두 문자열을 한 번씩 인덱스로 읽으며, 36개 칸을 한 번 검사합니다. n은 입력 문자열 하나의 길이입니다.

추가 공간 O(36) = O(1)

입력 문자열을 복사하지 않고 길이에 무관한 36개의 정수를 저장합니다.

경계 조건과 구현 안정성

  • 빈 입력: 두 문자열이 비어 있으면 delta는 모두 0이고 true입니다. 한쪽만 비어 있으면 길이 검사에서 false입니다.
  • 중복 문자: 방문 여부만 표시하지 않고 등장 횟수를 저장하므로 중복도 구분합니다.
  • 잘못된 입력: TokenIndex가 -1을 반환하면 배열에 접근하기 전에 거부합니다. 공백·소문자·UTF-8의 비 ASCII 바이트는 허용되지 않습니다.
  • 정수 범위: 최대 길이 200,000이라는 입력 계약에 따라 한 칸의 차이 절댓값도 200,000 이하로 32비트 int 범위에 들어갑니다.

대안 알고리즘의 비용

문자열 사본 둘을 정렬하고 비교하는 방법도 정확합니다. 일반적으로 정렬은 O(n log n) 시간을 쓰며, 원본을 유지하기 위한 사본에 O(n) 추가 공간이 듭니다. 이번 문제처럼 문자 집합이 36종으로 정해져 있으면 고정 카운트 방식이 더 간단합니다.

C++11 표준 모드에서 실제 컴파일했으며, 12개 고정 사례와 50,000개 난수 기반 비교, 길이 200,000 경계 테스트를 통과했습니다.

🚀 한 단계 확장 문제

문자열에서 아이템 ID 목록으로

두 입력이 더 이상 std::string이 아니라 std::vector<std::string>으로 주어진 아이템 ID 목록이라고 가정합니다. 가능한 ID의 종류는 무한히 많지만 중복 ID가 존재할 수 있습니다. 순서를 무시하고 같은 ID와 중복 횟수를 포함하는지 어떻게 검사할까요?

고정 36칸 배열이 더는 적절하지 않은 이유를 설명하고, std::sort와 std::unordered_map 접근법의 시간·공간 복잡도를 비교하세요. 해시 맵의 평균 시간과 최악 시간을 구분해서 생각해 보세요.
