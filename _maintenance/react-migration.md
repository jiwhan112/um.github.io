# ATLAS NOTE · React migration

## Runtime and build
All user-facing ATLAS NOTE pages use React 19, TypeScript 5, React Router 7 and Vite 7. Shared UI uses Radix primitives, shadcn-style source components, Tailwind 4 and a token stylesheet. Jekyll/legacy detail.js are not loaded by the React distribution. Old authoring HTML remains a build input only; see web/scripts/content.ts and the Block schema. No runtime DOM reparenting, HTML injection or iframe wrapping.

## Scheduled authors
Briefing: daily-briefing/data/YYYY-MM-DD.json and catalog. Language: language-study/data/english|japanese/NNN.json; leave catalog/progress reconciliation to the existing workflow. Thinking/opensource: catalog plus _content.html or adjacent validated content.json. Assets: experiment sources, PNG/audio/model files, evaluation and Markdown report. New details must be registered in the relevant catalog.

Never write generated index.html, assets/react, data/atlas, build-info.json or language-study/sw.js in a content task. A content change triggers validation and publication. Failed validation retains the last compiled release. The publisher refuses to overwrite a document's authoring source.

## Publication
The repository continues to publish from master/root. The workflow builds with Vite, runs unit, browser, offline and visual tests, then writes only generated entry HTML, hashed assets, derived JSON and worker to that source. .nojekyll disables Jekyll processing of the compiled app. The workflow explicitly requests a Pages build because GITHUB_TOKEN pushes do not trigger new push workflows. Remote-head changes invalidate stale publications. No force-push is used. Older hashed bundles remain available for already-open sessions. Original JSON/PNG and _content.html are preserved. Each current route has a real index.html for direct navigation/reload. Old language hash links resolve to the clean React routes.

## User state
Preserve jiwhan-briefing-v1 date:index IDs, the original four thinking-ctci-...-draft raw string keys, atlas-reading-v1 and atlas-language-sections-v1. Never clear localStorage. The language worker retires only language-study-* caches. TTS uses the device's browser voices; the UI has no C++ execution engine.

## Tests and recovery
cd web && npm ci && npm run check. Visual fixtures pin representative real content, while functional tests use all current production content. Reviewed screenshots are never automatically regenerated by the publication workflow. Deliberate updates require inspecting image diffs before changing baselines. The pre-React release is commit 3e5c2fb0df3af38aa989888107fee5780cea5e9e; preserve a backup branch. Roll back a complete release and its publisher together, never CSS alone.
