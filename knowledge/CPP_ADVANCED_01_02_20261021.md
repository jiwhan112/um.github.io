## 구성과 원본 보존

각 단원은 개념과 원리 / 실습·복습 / 출처·검증 / 원문·변경기록의 네 탭으로 구성한다. 두 단원에 직접 제작한 SVG 6개, 렌더링용 Mermaid 3개, 접힌 복습 답안 17개를 넣었다. 긴 전체 코드는 접어서 읽으며 실제 다운로드 파일과 정확히 같은 문자열이다.

01은 체력의 유효 범위, 생성·소멸 순서와 생성자 실패를 그림으로 비교한다. 생성 중인 멤버가 남긴 이벤트와 생성 완료는 다르며, 실패한 객체와 이미 완성된 하위 객체의 정리를 구분한다. 02는 관찰 주소와 소유권, 복사와 이동, `IntBuffer`의 메타데이터와 자원 관계, 후보 상태의 검증·교체를 설명한다. 실패 주입 플래그 소비, 미지정 인수 평가 순서, 동시성과 외부 부수 효과 등 예제가 보장하지 않는 범위를 명시한다.

각 `source-notion.md`에는 Notion fetch가 반환한 `<content>` 내부 본문과 마지막 LF를 보존한다. 조상 페이지 wrapper는 게시하지 않는다. 페이지 수정 시각, 응답 기준 시각, 바이트 수와 SHA-256은 capture JSON에 기록한다. 도구가 제공하지 않은 `truncated`·`unknown_block_count`는 `null`이다.

상위 Notion 원문에 과거 대화 첨부로만 남아 있다고 기재된 ZIP과 전체 소스 Markdown을 실제로 복구했다. ZIP의 SHA-256은 Notion 검증 첨부에 적힌 값과 일치한다. 44개 ZIP 파일은 원본 소스·설정·문서 22개와 과거 원시 로그 22개로 나누어 바이트 그대로 보존한다.

소스 Markdown의 21개 코드 블록은 대응하는 ZIP 파일보다 마지막 LF가 하나 더 있다. 두 원본을 바꾸지 않고 이 관계와 각 해시를 [무결성 원장](shared/cpp-advanced-lab/source-integrity.json)에 남겼다. Notion 검증 첨부의 실패 예제 6개는 ZIP 파일과 바이트가 같다. 원본 ZIP은 실제 정적 다운로드 자원으로 제공하며, 빌드에서 해당 파일만 명시적으로 허용한다.

한국어 주석판 `check.hpp`, `lifetime.cpp`, `ownership.cpp`, `transaction.cpp`는 각각 244·734·1,110·475개의 매크로 확장 전 C++ 토큰과 전처리 지시문이 원본과 같다. 주석·공백에 의한 `__LINE__` 위치 차이는 각 파일의 실제 줄 번호를 따른다. 이 비교는 해당 파일의 변경 범위를 확인하는 검사이며 일반적인 C++ 의미 동등성 증명은 아니다.

## 이번 실행 근거

[새 로컬 원시 기록](shared/cpp-advanced-lab/verification/local-gcc-20261021/README.md)은 GCC 13.3.0 C++20에서 원본 9개와 한국어판 3개 모두 빌드·실행 성공, 출력 3쌍 바이트 일치를 기록한다. 경고를 오류로 처리했다. 실패 예제 6개 예상 컴파일 거부와 엄격한 C++11 원본 9개 미지원 진단도 별도로 보존했다. 원시 출력·환경·결과 46파일, 89,144바이트와 해시 manifest가 있다.

로컬 환경에는 Clang·CMake·CTest가 없어 해당 구성은 GitHub Actions에서 실행했다. [새 CPU CI 39557286731](https://github.com/jiwhan112/um.github.io/actions/runs/39557286731)은 소스 커밋 `4cbd10710d0bfce8cb93fae89a9545369c797985`에서 네 작업 모두 성공했다. CMake 3.31.6, GCC 13.3.0 C++20 및 Clang 18.1.3 C++20 + ASan/UBSan에서 각각 Configure·Build와 **CTest 12/12**, 출력 3쌍 바이트 일치를 확인했다. 실패 예제 6개를 각 컴파일러에서 별도 확인하고 GCC의 엄격한 C++11 원본 9개 미지원 진단도 분리했다.

GitHub artifact 4개의 ZIP SHA-256을 API digest와 대조한 뒤 원시 파일 **55개, 261,873바이트**를 보관했다. [이번 실행 원장](shared/cpp-advanced-lab/verification/github-39557286731/README.md)과 [artifact·파일별 SHA-256](shared/cpp-advanced-lab/verification/github-39557286731/artifact-manifest.json)에서 원시 Configure·Build·CTest, 실패 진단과 실행 환경을 확인할 수 있다. 이 원시 로그 보관·문서 설명 추가는 검증 대상 소스 커밋 다음의 별도 커밋이며, 최종 head의 CI도 다시 확인한다.

웹 단위 검사 **30/30**, TypeScript·React production build, **154개 직접 진입 경로와 내부 링크 검사**가 통과했다. [웹 CI 39557286590](https://github.com/jiwhan112/um.github.io/actions/runs/39557286590)은 **PC·모바일 429개 통과, 의도적 제외 1개, 실패·불안정 재시도 0개**로 성공했다. 모든 교재·탭의 Mermaid 89개를 실제 렌더링했다. 모바일의 전체 Mermaid 중복 검사 1개만 제외하며 개별 모바일 렌더링·확대·배치 검사는 별도로 실행한다.

웹 artifact ZIP의 SHA-256 `9ce81cdf89e04e8b8f1ba84cbb345609fa8dded9e99c3b9192f96110ffdd644a`를 확인하고, 두 단원의 PC·모바일 첫 화면·전체 본문·한국어 소스 캡처를 검토했다. 첫 화면에서 좌측 회차 목록이 URL의 알파벳 순서 때문에 심화를 기초보다 먼저 표시하는 것을 발견했다. 학습 목차·이전/다음과 동일한 순서가 되도록 C++ 링크만 제자리에 재배열하고 PC·모바일 메뉴 검사로 확인한다. 심화 01 Mermaid의 비교식 `amount >= current?`에서 화면상 `>` 문자가 사라지는 것도 발견했다. 도식의 조건을 “피해량이 현재 체력 이상?”과 “피해량이 음수인가?”로 바꾸고, 생성된 SVG의 실제 라벨을 검사한다. C++ 코드의 비교 연산과 보존 원문은 그대로 둔다. 모바일에서 어미만 다음 줄에 남은 제목 여섯 곳을 짧게 다듬고, 전체 소스 표 첫 열을 한국어 실습명으로 바꾸어 파일명이 한 글자씩 쪼개지는 문제도 줄였다. 추가한 원시 로그와 이 두 수정은 최종 head에서 모든 회귀 검사를 다시 통과한 뒤 병합한다. 공개 배포는 해당 실행과 실제 공개 URL 확인 뒤 판정한다.

### 검사 수와 검증 한계

- 원본 팩 전체는 89회 검사 호출이며, 이번 단원에 해당하는 범위는 31회(10+13+8)다. 한국어판·여러 컴파일러·출력 비교를 위한 재실행을 독립 조건으로 더하지 않는다.
- `ownership`의 13회 중 `Expect(true)` 1회는 prvalue 구성 예제 이후의 도달 표시다. 해당 예제는 컴파일 성공이 핵심 근거이며 `static_assert` 2개도 런타임 호출과 구분한다.
- C++11 거부 진단은 호환 빌드 성공이 아니다. 실습 팩은 C++20 기준이며 별도의 C++11 이식판을 임의로 만들지 않았다.
- 과거 GCC 14.2·Clang 17의 CTest 9/9 로그는 `verification/historical-20261013/`에 보존한다. 이를 새 환경의 실행 결과로 재사용하지 않는다.
- Windows/MSVC·Direct3D11·GPU·HLSL 컴파일은 미검증이다. 동시성·실제 게임 통합·ABI·성능·모든 예외 지점과 입력도 검증하지 않았다.

## 목차와 기존 기능

사이트맵·좌측 회차 목록·모바일 메뉴와 교재 하단의 이전·다음 링크는 **기초 01~05 → 심화 01~02** 순서다. URL 알파벳 정렬에서 심화가 먼저 나오지 않도록 C++ 과정 비교 함수를 추가했다. DirectX 11의 기존 순서와 다른 분류는 유지한다.

브리핑·언어·사고력·게임 기획 원본, 저장 키, Supabase 설정, 예약 작업, 기존 공개 URL은 변경하지 않는다. Notion은 읽기 전용으로 사용한다. 기존 승인 화면의 기준 이미지를 자동 갱신하거나 검사를 완화하지 않는다.
