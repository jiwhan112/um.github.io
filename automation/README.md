# ATLAS NOTE 예약 발행 계약

운영 UI는 React + TypeScript이며 모든 경로는 메인의 **dark** 테마를 사용합니다. 페이지별 레이아웃(뉴스 리더, 언어 교재, 문제 풀이, 갤러리)은 별개입니다. 콘텐츠 발행 작업은 화면·테마·메뉴·컴포넌트를 수정하지 않습니다.

## 실제 예약 작업과 변경 범위

`publishing.json`은 단일 일일 파이프라인의 식별자·시작 시각(Asia/Seoul), 두 일일 콘텐츠 단계의 순서·허용 원본 경로를 기록한 운영 계약입니다. 이 JSON 자체가 ChatGPT 작업을 등록하거나 실행하지는 않습니다. 예약 작업 도구의 설정도 함께 갱신해야 합니다.

| 단계 | 실행 순서 | 수정하는 원본 |
| --- | --- | --- |
| 게임·AI 브리핑 | 매일 05:00 KST 시작 | 날짜별 JSON + 뉴스 카탈로그; 기존 Google Drive MD/PDF 보관 유지 |
| 영어·일본어 | 브리핑 발행·Drive 보관 완료 직후 | 언어별 레슨 JSON 각각 한 개; 카탈로그·진도는 reconcile 작업만 수정 |

2026-10-24부터 매일 05:00 KST에 시작하고 각 단계가 실제 게시까지 완료되면 다음 단계를 즉시 실행합니다. 각 단계의 완료 시각을 보장한다는 뜻은 아닙니다. 별도의 06:00·08:00·09:00 발행 예약은 사용하지 않습니다. AI 실험과 오픈소스 분석은 사용자가 지시할 때만 수행하고 예약 발행을 추가하지 않습니다.

## 사고력 훈련 실패 감시와 자동 복구 이력

2026-10-21 오전 06시 사고력 훈련 2.4 Partition 실행에서는 GitHub `update_ref`와 PR 생성이 안전 검사에 차단되어 작성한 원고가 `master`에 반영되지 않았습니다. 해당 실행이 예약 작업 자신까지 꺼 버려 10월 22일 06시 정기 발행도 실행되지 않았습니다. 이후 2.4와 2.5를 수동으로 복구·검증했습니다.

- **현재 사고력 발행:** 2026-10-27 사용자 요청으로 일일 예약에서 제외. 검증된 책 진도까지 연속 실행하며 새 예약은 만들지 않는다. 아래 과거 장애 이력은 유지한다.
- **별도 발행 누락 점검:** 예약 작업 `6adabd1af4d88191a4e650b62fdb5af2`는 2026-10-23 사용자 요청으로 일시정지. 같은 연속 발행 실행이 최종 검증과 복구를 수행한다.
- 사고력 연속 작업은 실제 `master`의 원본, 계획과 카탈로그, 미완료 배치, React CI/Pages를 먼저 확인합니다. 하루 여러 주제를 허용하며 기본·심화 두 페이지와 색인을 원자적으로 게시합니다. 기존 일자·주소·메모는 그대로 보존합니다.
- GitHub 쓰기/PR/CI가 실패해도 남은 브리핑·언어 일일 예약을 임의로 비활성화하지 않습니다. 별도 점검 작업은 사용자 요청으로 중지되어 있으므로 자동 재활성화하지 않습니다. 같은 발행 실행에서 허용된 복구를 수행하고 해결되지 않으면 원인을 보고합니다.
- GitHub 업데이트는 원자적 tree/commit 및 `update_ref(expected_sha)`가 우선입니다. API의 안전 검사가 이를 거부하는 경우 실패한 SHA와 실제 오류를 보고하고, 허용된 Contents API 대체 경로를 사용하더라도 원본 파일 저장 → 실제 조회 → 카탈로그 갱신 → React CI/Pages 검증 순서를 지키며 중간 실패는 미발행으로 처리합니다.
- 이 JSON의 `jobs`는 **브리핑·언어 순차 콘텐츠 단계 2개**이고 `pipeline`만 실제 활성 예약을 가리킵니다. 별도 `healthChecks`는 중지 상태의 기록입니다. JSON만 바꿔도 ChatGPT 예약이 생성되거나 활성화되지는 않습니다. 실제 예약 도구 상태를 우선 확인합니다.

## 공통 절차

1. 실행 당시 `master`의 `AGENTS.md`, 이 문서, `publishing.json`, `web/src/lib/types.ts`, `web/scripts/content.ts`와 최신 원본을 읽습니다. 화면을 읽어서 진도를 추측하지 않습니다.
2. 오늘 날짜(한국시간)와 연속 번호를 확인합니다. 뉴스·언어는 오늘 자료가 있으면 새로 만들지 않고 완성 여부만 확인합니다. 사고력은 날짜당 제한 대신 계획의 정확한 주제 순서와 기존 완성 쌍을 확인합니다. 과거 회차·아이템 순서·저장 키·연구 결과는 보존합니다.
3. 허용된 콘텐츠 원본만 작성합니다. 새 문제는 아래 `content.json` 규칙을 따릅니다. 뉴스와 언어는 기존 JSON 필드 계약을 따릅니다.
4. 날짜별 뉴스와 카탈로그, 문제와 카탈로그처럼 함께 필요한 변경은 단일 commit/tree로 반영합니다. 언어는 영어·일본어 완성본을 함께 커밋합니다. 최신 부모 SHA 확인 후 충돌하면 최신 자료를 읽어 병합하며 force push하지 않습니다.
5. 콘텐츠 검사/빌드/테스트가 실패하면 원본 오류만 수정하고 실패한 단계를 보고합니다. 검사나 CSS를 바꿔 성공 처리하지 않습니다.
6. commit, React 검증, 실제 Pages 게시, Drive 보관을 구분하여 보고합니다. 확인하지 못한 단계를 성공이라 쓰지 않습니다.

## 사고력 전권 연속 작업의 검증 경계 (2026-10-27 변경)

`publishing.json.continuousTasks`의 사고력은 `scheduleEnabled=false`이며 예약이 아닙니다. `thinking-book-plan.json`은 책 본문 접근 기록이 아니라 번호·주제 메타데이터의 증거와 순서를 기록합니다. 저자 페이지가 전체 189문항을 확인하지만, 조사에서 번호 메타데이터를 확보한 것은 160개이고 29개가 빠져 있습니다. 6.5는 저자 Java 저장소의 Egg Drop과 저자 연결 JavaScript 저장소의 Jugs of Water가 충돌합니다. 따라서 현재 안전한 발행 구간은 **1.1–6.4의 47주제**이며 `complete=false`입니다. 6.5 이후를 추측하거나 전체 책을 확인했다고 보고하지 않습니다.

- `current`는 검증된 순서 중 마지막 작성·색인 완료 주제이며 실제 공개 완료는 별도 CI/Pages 증거로 확인합니다. `next`는 날짜 없는 다음 주제입니다. 검증 구간 끝에서는 명시적인 `blocked_source_conflict`를 유지하며, 전체 189개가 모두 개별 검증·발행되기 전 `next=null`로 완료 처리하지 않습니다.
- 기존 19주제/38페이지의 날짜·주소·메모를 보존합니다. 새 주제는 실제 한국 게시일로 `study_date=published_date`를 기록하고 같은 날 여러 주제를 허용합니다. 미래 예약 날짜와 임의 과거 일괄 보충은 만들지 않습니다. 자정을 넘긴 게시라면 실제 게시일을 확인·조정하고 그 전에는 완료라고 보고하지 않습니다.
- 현재 승인된 다음 배치는 3.3–5.8의 24주제/48페이지입니다. 번호를 건너뛰지 않고 쌍을 완성합니다. 계획의 메타데이터 증거는 문제 지문·공식 풀이 복제 허가나 본문 확인을 뜻하지 않습니다.
- 교재·브리핑·언어 작업과 단일 원격 쓰기/배포 잠금을 공유합니다. 최신 부모 SHA와 진행 중 배치를 읽고 중복 원고·덮어쓰기·force push 없이 통합합니다. 원고 저장 → 커밋 → React 검사 → Pages → 공개 URL 확인을 구분합니다.

## 사고력 문제 라이브러리의 메타데이터

카탈로그 episode는 기존 `number`, `chapter`, `topic_en`, `title`, `summary`, `study_date`, `published_date`, `path` 외에 **`category`와 `tags`**가 필수입니다. `category`는 책의 장/분야(예: 배열과 문자열), `tags`는 중복 없는 1~8개의 짧은 알고리즘 주제입니다. 날짜·상태·문제 번호·“정답 접힘” 같은 UI 문구는 태그로 넣지 않습니다. 기존 태그 표기를 재사용하고 필요하면 새 주제를 추가할 수 있습니다.

현재 태그 예: 문자열, 중복 검사, 해시 테이블, 순열, 문자 빈도, 두 포인터, 제자리 수정, 회문, 비트 연산. 검색은 번호·제목·요약·영문 주제·분류·태그를 대상으로 하며 정답 본문을 검색 목록에 노출하지 않습니다. 태그를 여러 개 선택하면 모두 포함한 문제만 표시합니다.

2026-10-27 승인된 형식은 **한 주제당 두 독립 페이지**입니다. 기본은 `X.Y.1`, 심화는 `X.Y.2`이며 각 페이지에 문제 하나만 둡니다. 기본 경로 `thinking-lab/ep-XX-YY-slug/`와 심화 경로 `thinking-lab/ep-XX-YY-02-slug/`의 `content.json`을 카탈로그와 함께 게시합니다. 기존 기본 주소·메모·학습일·게시일은 보존하고 심화에는 독립 메모 키를 사용합니다. 카탈로그 `current`/`next`는 `X.Y` 주제를 세며 페이지 두 개 때문에 진도를 두 번 전진하지 않습니다. 현재 배치의 모든 기본·심화 페이지를 실제 공개 확인한 뒤 다음 책 진도로 진행합니다. 사고력은 일일 파이프라인에 포함하지 않습니다.

문제는 게임·개발 배경에 억지로 맞추지 않습니다. 인터뷰형 알고리즘, 논리 추리, 일상 규칙, 조합 퍼즐, 코드 없이 풀 수 있는 문제를 섞되 최근 유형을 확인해 반복을 피합니다. 기존 주제의 핵심은 유지하되 지문과 해설은 독창적으로 작성합니다. 각 페이지는 쉬운 말의 문제와 예시, 접힌 힌트 3개, 추론/상태 변화를 보여주는 그림 풀이와 숨긴 정답을 포함합니다. 코딩 문제의 입력·인코딩·버퍼 조건은 접힌 세부 조건으로, 비코딩 문제는 논증·검산·반례로 검증합니다. 코드가 없는 문제에 불필요한 코드를 강요하지 않습니다.

필수 본문 구조:

```json
{
  "title": "자체 제작 문제 제목",
  "subtitle": "스포일러 없는 설명",
  "memoKey": "thinking-ctci-장.문항-draft",
  "starter": "// C++11 시작 코드",
  "sections": [
    {"id":"problem","title":"문제","tab":"problem","blocks":[{"type":"paragraph","content":[{"text":"지문·입력 제약·예시"}]}]},
    {"id":"hints","title":"힌트","tab":"hints","blocks":[{"type":"details","title":"힌트 1","blocks":[{"type":"paragraph","content":[{"text":"힌트"}]}]}]},
    {"id":"solution","title":"풀이와 검증","tab":"solution","blocks":[{"type":"details","title":"정답과 검증 보기","blocks":[{"type":"code","language":"cpp","text":"// 실제 풀이"}]}]}
  ]
}
```

이 예시는 데이터 형식만 보여줍니다. 실제 발행에는 독창적 지문, 단계별 힌트, 그림 풀이·증명·경계/반례·복습을 충분히 작성합니다. 코딩형일 때만 접힌 입력/인코딩/버퍼 전제와 전체 C++11 풀이·복잡도·실행 테스트를 추가합니다. 실행하지 않은 코드를 테스트했다고 기록하지 않습니다. 도서 지문·공식 해설은 복제하지 않습니다.

`id`, `route`, `kind`, 날짜, 번호, 태그, 원본 경로·해시는 빌드가 카탈로그 및 실제 파일에서 결합합니다. `index.html`, 스크립트, 스타일, textarea를 작성할 필요가 없습니다. 예전 `_content.html`은 기존 자료의 보존 입력으로만 유지합니다. 도형은 지원되는 `diagram` 블록을 사용하거나 실제 생성된 자산을 이미지 블록으로 참조합니다.

## 언어 및 브리핑

언어 JSON 경로와 필드 스키마, 발음·해석·TTS에 쓰는 텍스트를 유지합니다. `Reconcile language lessons`는 레슨 push 또는 09:10 KST 보조 실행에서 카탈로그/진도를 재생성합니다. React 배포는 raw 레슨 push와 경쟁하지 않고 이 작업의 성공 뒤 최신 master를 빌드합니다. UI/워크플로 또는 다른 원본 변경은 평소처럼 React 배포를 시작합니다.

브리핑은 2026-10-19부터 고정 5개 제한 없이 검증된 중요 소식만 가변 개수로 기록하며, AI/게임 개발/게임 전반 이슈의 세 분야와 depth=deep|brief를 구분한다. 심층은 배경·원리·실무 의미까지 자세하게, 간략은 핵심 2~4문장으로 기록한다. 기존 과거 기사 순서·ID는 유지한다. 각 기사에서 `easy_explainer`, `short_summary`, `technical_context`, `why_it_matters`, `developer_view`, 실제 출처·날짜·URL을 유지합니다. `short_summary`는 문자열 또는 짧은 문장 배열을 지원합니다. 기존 `date:index` 기사 식별자를 위해 과거 items를 재정렬하지 않습니다. Drive 원문은 기존 MD/PDF 및 토요일 주간 보관 규칙을 유지합니다. 이 문서 정리 때문에 보관 양식을 바꾸지 않습니다.

## 화면 검증

일반 CI/배포는 스크린샷을 자동 갱신하지 않습니다. UI 변경 요청으로 의도한 디자인 변경이 있을 때만 후보 캡처를 직접 검토한 뒤 기준 이미지를 수정하고 다시 전체 검사를 통과시킵니다. 모든 경로와 검색 대화상자·모바일 메뉴에도 dark 토큰이 유지되는지 확인합니다.

## 게임 기획 연구실 이미지 가이드
