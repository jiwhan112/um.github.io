# ATLAS NOTE 예약 발행 계약

운영 UI는 React + TypeScript이며 모든 경로는 메인의 **dark** 테마를 사용합니다. 페이지별 레이아웃(뉴스 리더, 언어 교재, 문제 풀이, 갤러리)은 별개입니다. 콘텐츠 발행 작업은 화면·테마·메뉴·컴포넌트를 수정하지 않습니다.

## 실제 예약 작업과 변경 범위

`publishing.json`은 연결된 ChatGPT 예약 작업 3개의 식별자, 현재 발행 시각(Asia/Seoul), 허용 원본 경로를 기록한 운영 계약입니다. 이 JSON 자체가 ChatGPT 작업을 등록하거나 실행하지는 않습니다. 예약 작업 도구의 설정도 함께 갱신해야 합니다.

| 작업 | 시작 시각 | 수정하는 원본 |
| --- | --- | --- |
| 사고력 훈련 | 매일 06:00 | `thinking-lab/data/catalog.json` + 새 회차 `content.json` |
| 게임·AI 브리핑 | 매일 08:00 | 날짜별 JSON + 뉴스 카탈로그; 기존 Google Drive MD/PDF 보관 유지 |
| 영어·일본어 | 매일 09:00 | 언어별 레슨 JSON 각각 한 개; 카탈로그·진도는 reconcile 작업만 수정 |

시각은 기존 활성 작업의 명시적 설정을 유지합니다. 실행·배포 완료 시각을 보장한다는 뜻은 아닙니다. AI 실험과 오픈소스 분석은 사용자가 지시할 때만 수행하고 예약 발행을 추가하지 않습니다.

## 공통 절차

1. 실행 당시 `master`의 `AGENTS.md`, 이 문서, `publishing.json`, `web/src/lib/types.ts`, `web/scripts/content.ts`와 최신 원본을 읽습니다. 화면을 읽어서 진도를 추측하지 않습니다.
2. 오늘 날짜(한국시간)와 연속 번호를 확인합니다. 오늘 자료가 있으면 새로 만들지 않고 완성 여부만 확인합니다. 과거 회차·아이템 순서·저장 키·연구 결과는 보존합니다.
3. 허용된 콘텐츠 원본만 작성합니다. 새 문제는 아래 `content.json` 규칙을 따릅니다. 뉴스와 언어는 기존 JSON 필드 계약을 따릅니다.
4. 날짜별 뉴스와 카탈로그, 문제와 카탈로그처럼 함께 필요한 변경은 단일 commit/tree로 반영합니다. 언어는 영어·일본어 완성본을 함께 커밋합니다. 최신 부모 SHA 확인 후 충돌하면 최신 자료를 읽어 병합하며 force push하지 않습니다.
5. 콘텐츠 검사/빌드/테스트가 실패하면 원본 오류만 수정하고 실패한 단계를 보고합니다. 검사나 CSS를 바꿔 성공 처리하지 않습니다.
6. commit, React 검증, 실제 Pages 게시, Drive 보관을 구분하여 보고합니다. 확인하지 못한 단계를 성공이라 쓰지 않습니다.

## 사고력 문제 라이브러리의 메타데이터

카탈로그 episode는 기존 `number`, `chapter`, `topic_en`, `title`, `summary`, `study_date`, `published_date`, `path` 외에 **`category`와 `tags`**가 필수입니다. `category`는 책의 장/분야(예: 배열과 문자열), `tags`는 중복 없는 1~8개의 짧은 알고리즘 주제입니다. 날짜·상태·문제 번호·“정답 접힘” 같은 UI 문구는 태그로 넣지 않습니다. 기존 태그 표기를 재사용하고 필요하면 새 주제를 추가할 수 있습니다.

현재 태그 예: 문자열, 중복 검사, 해시 테이블, 순열, 문자 빈도, 두 포인터, 제자리 수정, 회문, 비트 연산. 검색은 번호·제목·요약·영문 주제·분류·태그를 대상으로 하며 정답 본문을 검색 목록에 노출하지 않습니다. 태그를 여러 개 선택하면 모두 포함한 문제만 표시합니다.

새 회차는 `thinking-lab/ep-XX-YY-slug/content.json`에 작성합니다. 필수 본문 구조:

```json
{
  "title": "자체 제작 문제 제목",
  "subtitle": "스포일러 없는 설명",
  "memoKey": "thinking-ctci-장.문항-draft",
  "starter": "// C++11 시작 코드",
  "sections": [
    {"id":"problem","title":"문제","tab":"problem","blocks":[{"type":"paragraph","content":[{"text":"지문·입력 제약·예시"}]}]},
    {"id":"hints","title":"힌트","tab":"hints","blocks":[{"type":"details","title":"힌트 1","blocks":[{"type":"paragraph","content":[{"text":"힌트"}]}]}]},
    {"id":"solution","title":"풀이와 검증","tab":"solution","blocks":[{"type":"details","title":"정답과 검증 보기","blocks":[{"type":"code","language":"cpp","text":"// 실제 풀이"}]}]}
  ]
}
```

이 예시는 데이터 형식만 보여줍니다. 실제 발행에는 입력/인코딩/버퍼 전제, 독창적 지문, 단계별 힌트, C++11 풀이·증명·복잡도·경계 테스트·확장 문제를 충분히 작성합니다. 실행하지 않은 코드를 테스트했다고 기록하지 않습니다. 도서 지문·공식 해설은 복제하지 않습니다.

`id`, `route`, `kind`, 날짜, 번호, 태그, 원본 경로·해시는 빌드가 카탈로그 및 실제 파일에서 결합합니다. `index.html`, 스크립트, 스타일, textarea를 작성할 필요가 없습니다. 예전 `_content.html`은 기존 자료의 보존 입력으로만 유지합니다. 도형은 지원되는 `diagram` 블록을 사용하거나 실제 생성된 자산을 이미지 블록으로 참조합니다.

## 언어 및 브리핑

언어 JSON 경로와 필드 스키마, 발음·해석·TTS에 쓰는 텍스트를 유지합니다. `Reconcile language lessons`는 레슨 push 또는 09:10 KST 보조 실행에서 카탈로그/진도를 재생성합니다. React 배포는 raw 레슨 push와 경쟁하지 않고 이 작업의 성공 뒤 최신 master를 빌드합니다. UI/워크플로 또는 다른 원본 변경은 평소처럼 React 배포를 시작합니다.

브리핑은 2026-10-19부터 고정 5개 제한 없이 검증된 중요 소식만 가변 개수로 기록하며, AI/게임 개발/게임 전반 이슈의 세 분야와 depth=deep|brief를 구분한다. 심층은 배경·원리·실무 의미까지 자세하게, 간략은 핵심 2~4문장으로 기록한다. 기존 과거 기사 순서·ID는 유지한다. 각 기사에서 `easy_explainer`, `short_summary`, `technical_context`, `why_it_matters`, `developer_view`, 실제 출처·날짜·URL을 유지합니다. `short_summary`는 문자열 또는 짧은 문장 배열을 지원합니다. 기존 `date:index` 기사 식별자를 위해 과거 items를 재정렬하지 않습니다. Drive 원문은 기존 MD/PDF 및 토요일 주간 보관 규칙을 유지합니다. 이 문서 정리 때문에 보관 양식을 바꾸지 않습니다.

## 화면 검증

일반 CI/배포는 스크린샷을 자동 갱신하지 않습니다. UI 변경 요청으로 의도한 디자인 변경이 있을 때만 후보 캡처를 직접 검토한 뒤 기준 이미지를 수정하고 다시 전체 검사를 통과시킵니다. 모든 경로와 검색 대화상자·모바일 메뉴에도 dark 토큰이 유지되는지 확인합니다.

## 게임 기획 연구실 이미지 가이드
`game-design/data/catalog.json`과 `game-design/ep-*/content.json`, 해당 회차의 `assets/*.svg|png|webp|jpg|jpeg`만 자동 제작 범위입니다. 영상 내용을 실제로 검증하고 사쿠라이 설명과 독자의 C++ 구현 관점을 구분합니다. 한 회차당 핵심 기획 포인트를 설명하는 그림을 1~3개 권장합니다. 시간선·의사결정 트리·상태 전이·수치 조절 비교는 한글 라벨이 포함된 오리지널 SVG로, 시각화가 필요한 환경·게임 플레이 상황은 권리 문제 없는 직접 생성 이미지를 사용합니다. `image` 블록에는 `src`, `alt`, `caption`을 포함하며 `src`는 해당 회차의 `/game-design/ep-.../assets/...`에서 참조합니다. 웹 빌드가 에셋을 복사하고 누락·위험 SVG·내부 링크를 검증하도록 설정되어 있습니다. 검증 불가능한 이미지 출처를 허위로 표시하지 않습니다.
