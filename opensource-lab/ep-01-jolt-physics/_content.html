Jolt Physics: 게임 물리 엔진은 어떻게 충돌을 처리할까?

실제 게임 제작에 쓰이는 유명 오픈소스의 설계 의도, 핵심 자료구조, 처리 흐름을 살펴봅니다. 특정 개발 환경이나 개인 프로젝트 적용법은 다루지 않습니다.

분야: 물리 시뮬레이션언어: C++소스: jrouwe/JoltPhysics ↗

왜 Jolt Physics를 살펴볼까?

Jolt Physics는 게임·VR 용도로 설계된 오픈소스 강체 물리 및 충돌 감지 라이브러리입니다. 멀티코어에서 물리 데이터를 처리하면서 동시에 충돌 질의, 객체 추가·제거 등 여러 작업을 다루도록 설계했습니다. Godot 4.4부터 3D 물리 엔진 옵션으로 통합된 사례도 있습니다.

📦 강체(Rigid body)

상자, 공, 바닥 등 위치·속도·질량을 가진 물리 객체를 모델링합니다.

🔍 충돌 감지

서로 만날 가능성이 있는 객체를 찾고 실제 접촉 여부를 정교하게 판별합니다.

⚙️ 제약과 응답

접촉 지점과 관절 제약을 이용해 물리적으로 일관된 움직임을 계산합니다.

그림으로 이해하는 충돌 처리

핵심 관찰

성능은 “충돌 계산이 빠르다” 하나로 끝나지 않습니다. 쓸모없는 검사 대상을 최대한 줄이고, 데이터 접근과 병렬 실행을 잘 관리하는 구조가 중요합니다.

소스 코드를 읽을 때 확인할 구조

PhysicsSystem

시뮬레이션의 주요 시스템 객체. 물리 세계를 구성하고 업데이트하는 큰 흐름을 관찰합니다.

BodyInterface

강체 생성·추가·제거 등 외부에서 물리 객체를 다루는 인터페이스를 살펴봅니다.

ObjectLayer

어떤 종류의 물체끼리 충돌 대상으로 삼을지 분류하는 방법을 연구합니다.

BroadPhaseLayer

거친 공간 검색 단계에 사용할 객체 그룹을 구분하는 방식을 살펴봅니다.

구조의 이름과 역할을 소개하는 입문 해설입니다. 특정 릴리스·커밋에서 함수 구현을 계측하거나 성능을 실측한 분석은 아닙니다.

기술적으로 생각해 볼 질문

Q1. N개의 물체가 있을 때 모든 쌍을 검사하면 얼마나 비쌀까?

모든 서로 다른 쌍을 검사하면 N(N−1)/2번의 비교가 필요하므로 O(N²)입니다. 공간 분할을 활용하는 Broadphase는 실제로 검사할 후보 수를 줄이려는 단계입니다. 다만 최악의 경우가 항상 개선되는 것은 아닙니다.

Q2. 모든 물체가 서로 충돌해야 할까?

예를 들어 센서, 정적 지형, 서로 충돌하지 않는 장식용 객체 등을 구별할 수 있습니다. 레이어 기반 충돌 필터링은 불필요한 충돌 쌍을 줄이고 게임 규칙을 명확하게 표현합니다.

Q3. 병렬 처리에서 특별히 어려운 점은 무엇일까?

충돌 질의·객체 변경·시뮬레이션 갱신이 겹칠 수 있으므로 일관된 데이터 뷰와 작업 동기화가 필요합니다. Jolt의 설계 문서와 예제를 통해 이런 조건을 살펴볼 수 있습니다.
